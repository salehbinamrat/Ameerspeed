# تقرير فحص ومعالجة صفحة الأمير نت

**التاريخ:** 21 نوفمبر 2026  
**المصدر:** `hotspotالامير نت.zip` المرفق؛ مستودع `salehbinamrat/Ameerspeed` كان فارغا قبل بدء الرفع.  
**النطاق:** HTML وCSS وJavaScript محليان، MikroTik HotSpot / User Manager v6.

## المشكلات المتحققة

| البند | قبل المعالجة | الإجراء / النتيجة |
|---|---|---|
| زر الدخول على هاتف قصير | كان موضع بدء الزر عند نحو 826px من أعلى الشاشة عند 320×568، أسفل الجزء المعروض | تقليل ارتفاع الشعار والمسافات والبطاقات والحقول؛ أصبح الزر في الاختبار عند نحو 498px ويكتمل قبل 568px |
| الوصول السريع إلى نموذج الدخول | لا يوجد رابط أعلى الصفحة للانتقال مباشرة إلى النموذج | إضافة رابط واضح أعلى الصفحة يشير إلى `#loginCard` ويعمل دون JavaScript |
| عرض أقل من 320px | كان الحد الأدنى `.screen{min-width:320px}` | إزالته مع منع التمرير الأفقي |
| نافذة الترحيب | تظهر بعد 300ms مع طبقة تغطي كامل الصفحة وتختفي بعد 7s | تأخير الظهور إلى 1200ms، تقليل المدة إلى 3s؛ وتخفيف طبقة النافذة على الشاشات الصغيرة لتجنب حجب الضغط على نموذج الدخول |

| اختلاف عرض الشعار | استخدم `background-size:cover` ما قد يقص بعض أطراف الصورة | اعتماد `contain` مع احتفاظ الصورة الأصلية دون أي استبدال |
| أداء هواتف منخفضة المواصفات | blur/backdrop-filter متعدد في البطاقات | تعطيل التمويه الزجاجي على عرض الهاتف، تخفيف الظلال وتقصير الحركة عند تفعيل تقليل الحركة |
| تحميل JavaScript عند البداية | مكوّن الكاميرا ~37 KB يحمّل في كل زيارة حتى دون استخدامه | تحميله فقط عند الضغط على زر التصوير مع رسالة عند فشل التحميل؛ **الشفرة الأصلية لمكون الكاميرا لم تعدل** |
| إشارات اختيار السرعة | تتكرر requests صور و`fetch()` لكل منفذ | إلغاء نداءات `fetch()` المكررة مع المحافظة على 3 إشارات صور وتوقيت اختيار السرعة الأصلي |
| عدم وجود JavaScript | رابط `$(link-login-only)` لا يفسره ملف `index.html` الساكن دائما | تحديد نموذج الدخول HTML بنقطة `/login` المعتادة ليظل إرسال POST الأساسي متاحا عند تعطل JavaScript |
| التاريخ الهجري | `Intl.formatToParts` غير متاح في بعض المتصفحات القديمة | إضافة بديل `Intl.format()` عندما يكون متاحا |

## ما تم الحفاظ عليه

- نموذج إدخال الكرت، تحويل الأرقام العربية، إزالة الفراغات؛ وملفات HotSpot الخاصة بالـRouterOS (`login.html`, `status.html`, `logout.html`, `alogin.html` وغيرها).
- اختيار السرعة للـHotSpot والنطاقات User Manager، الإشارة إلى منافذ السرعات، والكرتان السابقان وإدارة ملف cookies.
- الإشعارات العربية المصنفة حسب خطأ الراوتر، وحالة الدخول والخروج والتحديثات والتبديل بين الكروت.
- تبويبات الأسعار ونقاط البيع والإرشادات، تبديل المظهر، تواصل العملاء، والرسائل الترحيبية.
- صورة الشعار الأصلية والخطوط الأصلية، وملف الكاميرا الأصلي كاملا دون إزالة وظيفته.

## الاختبارات المنفذة

- **7/7** اختبارات آلية ثابتة: الملفات المحلية، إرسال POST المباشر، وجود المدخلات، توافر رابط تسجيل الدخول، اتساق الخيارات، عدم تحميل الكاميرا في بداية الصفحة، وجود ملفات الكاميرا.
- فحوص Chromium المحلية (تخطيط CSS بدون راوتر) عند `280×560`, `320×568`, `360×640`, `375×667`, `430×932`؛ لا تمرير أفقي، زر الدخول ظاهر أو يمكن الوصول إليه قبل أسفل الشاشة، والمسارات محفوظة.
- **8/8** حالات اختبار لتصنيف أسباب رفض الكرت (الرصيد/البيانات/الصلاحية/الجلسات/المستخدم/خادم RADIUS/الباقة/رسالة مجهولة).
- **2/2** سيناريوهات استجابة RouterOS وهمية في Chromium: نجاح الدخول وظهور صفحة الحالة، ورفض الكرت مع بقاء زر إعادة المحاولة ورسالة الخطأ العربية.
- التحقق النحوي `node --check` لجميع ملفات JavaScript المحلية: نجاح.

**حدود الاختبار:** العرض في محاكاة Chromium الحديثة لا يساوي اختبار WebView لهاتف Android قديم. لم يتصل هذا التقرير براوتر MikroTik حقيقي؛ لا يدعي نجاح المصادقة أو وظائف الكاميرا أو إشارات User Manager في الإنتاج، ولا يقدم أرقاما مقاسة لزمن التحميل على الهواتف الفعلية.

## ملاحظات ومخاطر متبقية

1. `js/cam.najm.js` شفرة كبيرة مموهة تعتمد تنفيذ `new Function(...)` وترخيص/مطابقة اسم المضيف، وقد تظهر للمستخدم «الكاميرا مقفلة»؛ جرى الحفاظ عليها كما وردت، وليس بالإمكان ضمان أمنها أو فعاليتها دون مصدر الكاميرا الأصلي الواضح والترخيص المناسب.
2. نموذج `/login` المباشر يستهدف تسجيل HotSpot الافتراضي. اختيار نطاق User Manager والكاميرا لا يعملان دون JavaScript، ولا يمكن ضمان دعم CHAP الأصلي من هذا النموذج دون إعداد الراوتر وطريقة المصادقة.
3. لم تجر محاكاة كاملة لمحركات Android 4.x / Samsung Browser القديمة؛ يوصى باختبار ميداني على Android 5/6/7 وAndroid 10+، خاصة في نافذة captive portal الصغيرة.
4. يوصى بنسخة احتياطية قبل نشر الملفات على الراوتر، ثم تحقق تسجيل الدخول الفعلي من كرت صحيح وغير صحيح ومنتهي وقيد الاستخدام، ومن وظائف تهيئة الكرت التالي والخروج.
5. التغييرات على GitHub لا تنشر نفسها تلقائيا إلى أجهزة MikroTik.

## حالة الرفع إلى GitHub

جرت محاولة إنشاء ملف أولي باستخدام الاتصال الرسمي لـGitHub، ثم محاولة إنشاء Git blob. رفض GitHub العمليتين بالرمز `403 Resource not accessible by integration`، رغم إمكان قراءة بيانات المستودع. **لم ترفع الملفات ولم ينشأ commit أو Pull Request، وظل `main` دون تعديل.** النسخة المضغوطة المرفقة في المحادثة هي مخرجات العمل القابلة للتحميل. يتطلب الرفع عبر GitHub صلاحيات كتابة المحتوى، أو رفع الملفات من حساب المالك عبر واجهة GitHub.

## النشر الآمن

الاحتفاظ بالنسخة الأصلية؛ مراجعة المقارنة ونتائج الاختبارات؛ تجربة على راوتر غير إنتاجي أو مجموعة محدودة؛ ثم تعميم النسخة بعد تحقق الوظائف الأساسية. إذا ظهرت مشكلة مع نظام دخول خاص بـRouterOS/CHAP أو الكاميرا، يمكن العودة إلى الملفات الأصلية.
